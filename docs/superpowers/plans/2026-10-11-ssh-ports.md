# SSH Ports Implementation Plan

**Goal:** Proxy local HTTP domains to a remote loopback HTTP port using system OpenSSH stdio forwarding, without a local listening port.
**Architecture:** A per-route HTTP transport owns SSH-backed net.Conn instances. Each backend connection runs ssh -W; HTTP keep-alive reuses it. Editing/removing a route closes its old pool, shutdown closes all pools. Connections are lazy; failures retry on later requests with bounded backoff.
**Tech Stack:** Go standard library, system OpenSSH, embedded vanilla UI.
**Spec:** Approved conversation: SSH Ports with Domain name, SSH host alias, remote Target port; inherit host SSH config and agent; noninteractive key authentication only.

## Constraints
- No local Aux listener, no password collection, no writes to user SSH configuration.
- Fixed remote target 127.0.0.1; HTTP/WebSocket/stream support, preserve original HTTP Host.
- Explicit SSH options prevent background masters, configured listeners, local commands, interactive host-key acceptance.
- Saved SSH routes require neither Docker nor an active connection.
- Display observed connection state; distinguish SSH failure (503) from known forwarding/backend failure (502).
