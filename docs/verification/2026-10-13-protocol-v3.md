# Protocol v3 verification — 2026-10-13

Implementation: [architecture](../../DESIGN.md), [transport details](../ports-over-cloud-v1.md), and [security boundaries](../../PORTS_OVER_CLOUD.md).

## Result and scope

The production client and both relay entry points use protocol v3. Catalogs are
AEAD-encrypted and pairing uses opaque route identifiers. The E2E net.Conn layer
performs fresh XXpsk3 handshakes without replacing the connection passed to yamux.
All communicating clients and relays must be upgraded together; there is no v2 wire fallback.

Verification was local on macOS, darwin/arm64, Apple M4 Pro, Go 1.27.1. It used
isolated configurations and controlled services. The user's running port 8080
instance and saved configuration were not changed or restarted.

Standalone, embedded, and open-admission embedded relay cases all passed. Each

rejection and the control-frame size boundary; the final ordinary race suite
covered those fixes. The normal short integration run skips this expensive case.

Existing isolated integration tests also exercise HTTP, streaming, WebSockets,
remote administration, reconnect, revocation, wrong credentials, and trusted-CA
WSS. Peer unit tests exercise both renewal roles, saturated and unread streams,
credit bounds, deadlines, short I/O, fatal partial writes, authorization failure,
binding substitution and duplicate FINISH rejection. Catalog tests cover AEAD

Browser checks used an isolated full build on port 18880: Settings initially

## Measurements

Local microbenchmarks use one peer pair over net.Pipe with production policy.
Renewal is explicitly triggered by the benchmark; throughput uses one reader and
one writer with 256 KiB payloads. These are not WAN or multi-client load results.

| Measurement | Observed result |
| --- | --- |
| Handshake including pair setup/teardown | 527,846 ns/op; 60,763 B/op; 858 allocations/op |
| Fresh renewal | 414,341 ns/op; 41,101 B/op; 549 allocations/op |
| Maximum observed renewal completion interval | 1,102,417 ns |
| In-memory throughput | 553.33 MB/s; 1,720,234 B and 353 allocations per 256 KiB operation |

The renewal completion interval is a microbenchmark measurement, not a bound on
application latency. Ten repeated connection/renewal/disconnect cycles in the
resource test transferred 1 MiB each. After closure and GC, observed live heap
delta was 56,824 bytes and goroutines returned from 2 to 2. This does not measure
RSS, prove zeroization, or establish long-running production memory limits.

## Independent review and fixes

One independent agent reviewed the final protocol and lifecycle implementation
against the saved baseline. It reported no critical findings and three important
issues. All were addressed:

1. Closing a discarded yamux session while holding the client mutex could deadlock.
   Shutdown now occurs outside that mutex; a regression test failed before the fix.
2. Rejecting an oversized local catalog disconnected an otherwise healthy client.
   Local publication errors now preserve the usable publication and session, expose
   an error and allow recovery. The regression test failed before the fix.
3. Tests assigning state directly did not exercise real wire barriers. Tests now
   gate HS1, HS2, HS3 and both FINISH writes, each with close, cancellation, deadline,
   partial-ciphertext failure and timeout (25 combinations).

A minor size-boundary issue was also fixed: the 4 KiB control limit includes the
type byte. The regression test failed before the fix. No review findings were
left deferred. This review and passing tests are not an independent cryptographic audit.

## Execution decisions and limits

- The repository has no HEAD. Changes were made in place, retaining file-based
  baseline copies and the execution ledger under `.superpowers/sdd/`. No unrelated
  initial commit, branch merge or deployment was performed.
- Saved `/v2/ws` endpoint spelling remains loadable to preserve configuration;
  dialing always selects `/v3/ws`. There is no protocol downgrade. The saved
  spelling may therefore differ from the actual transport path.
- Long integration uses production thresholds and a test-only flag rather than
  exposing reduced renewal policy through production APIs. It is slower and must
  be requested explicitly.
- Actual monotonic timers and gated carriers replace the proposed fake-clock
  abstraction. They exercise real deadline behavior but can be sensitive to severe
  host stalls. Existing regression coverage was extended rather than duplicating
  every proposed test name.
- Browser coverage was narrower than the proposed manual matrix; protocol behavior
  is covered by automated isolated integration. No Linux/Windows runtime networking,
  real NAT/WAN/firewall deployment or external penetration testing was performed.
- Fuzz targets were added; no sustained fuzz campaign is claimed.

The relay still observes group/routing identifiers, traffic sizes and timing.
Catalog encryption uses the long-lived group secret: obtaining that secret can
expose recorded catalog history. Fresh-DH renewal applies to peer E2E sessions,
not the outer relay-admission connection. Transport loss closes streams and does
not transparently replay application requests or migrate them to a new path.
